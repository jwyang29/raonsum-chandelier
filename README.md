# 가상 샹들리에

Playground 파생작. 천 위에 손가락으로 그리면 크리스탈 하나가 태어나 천장의
가상 샹들리에에 매달린다. 관객은 자기 폰으로 QR 을 스캔해서 본다.

```
천 + ToF 9개 -> ESP32 -> (USB) -> 허브 -> Firebase -> 관객 폰 웹 AR
```

**https://jwyang29.github.io/raonsum-chandelier/**

## 로컬에서 보기

```
python3 -m http.server 5604 --directory web
```

열 때 쿼리를 붙인다.

| 쿼리 | 하는 일 |
|---|---|
| `?preview=1` | 마커도 카메라도 없이 샹들리에만 본다. 폰 성능을 보는 자리다 |
| `?mock=1` | Firebase 없이 가짜 크리스탈을 4초마다 만든다 |
| `?fill=1` | 쌓인 상태로 시작한다. `?fill=60` 처럼 개수도 준다 |
| `?desk=1` | 책상 시험용. 샹들리에를 마커 위 0.30~0.70m 로 줄인다 |
| `?msize=0.062` | 마커 검은 사각형의 실제 한 변 (m) |
| `?guide=1` | 마커 평면에 실측 윤곽과 1m 자를 그린다. 월드가 실물에 맞는지 본다 |
| `?debug=1` | 마커 수, 크리스탈 수, 품질 단계, fps, 월드 원점, 실측값을 표시한다 |

카메라는 HTTPS 또는 localhost 에서만 열린다. 폰으로 볼 때는 GitHub Pages 에 올려야 한다.

### 인쇄 전에 폰으로 확인하는 법

🔴 `?mock=1` 만 붙이면 **아무것도 안 보이는 게 정상이다.** AR 모드는 빈 상태로
시작하고(쌓인 것은 Firebase 에서 받는다), 샹들리에는 마커에서 1.7~3.1m 위라
책상에 놓은 마커를 비추면 화면 한참 위에 있다.

1. 노트북 화면에 마커를 띄우고 **검은 사각형을 자로 잰다**.
2. 폰에서 `?mock=1&fill=1&desk=1&msize=잰값&debug=1` 로 연다.
3. 진단 패널의 `보이는 마커` 가 올라가면 검출까지 된 것이다.

`msize` 를 안 주면 월드 전체가 그만큼 작아진다. AR.js 는 적어 놓은 마커 크기로
거리를 풀기 때문이다. 화면의 CSS mm 는 실제 mm 가 아니다.

### 인쇄

🔴 **`markers/print/` 의 PDF 로 100% 배율로 찍을 것.** SVG 를 브라우저에서
인쇄하면 여백에 맞춰 줄어든다. 찍고 나서 **자로 검은 사각형을 재서 100mm 인지
확인한다.** 여기가 틀리면 월드 전체의 크기가 그 비율로 틀어진다.
100mm 로 못 찍었으면 `web/config.js` 의 `markerSize` 를 실측값으로 고친다.

| 파일 | 내용 |
|---|---|
| `RAONSUM_marker_layout_A4.svg` | **배치도 한 장.** 평면도, 옆면도, 큐브 자리와 면 번호. 브라우저에서 인쇄 |
| `RAONSUM_markers_floor_A4.pdf` | 바닥 4장. 검은 사각형 100mm, 흰 여백 포함 150mm |
| `RAONSUM_marker_cube1.pdf` ~ `cube3.pdf` | 매단 큐브 5장씩 (옆면 4 + 밑면 1). 한 변 165 / 170 / 205mm |
| `RAONSUM_marker_ceiling_A4.pdf` | 천장 1장. **선택이다.** 큐브 밑면이 그 자리를 맡는다 |

무광으로, **흰 여백은 자르지 말 것.** 여백이 없으면 검출기가 사각형을 못 찾는다.

다시 뽑을 때. 배치도는 `config.js` 에서 치수를 읽어 오므로 좌대를 실측해서
고치면 다시 돌려야 한다.

```
python3 markers/make_pdf.py markers/print            # 마커. --cube 160 으로 큐브 크기 변경
python3 markers/make_layout.py markers/print         # 배치도 SVG
```

배치도는 브라우저에서 열어 인쇄하면 된다. 배율이 틀어져도 상관없는 참고용이다.

### 매단 큐브 만들기 (종이)

큐브 PDF 가 전개도다. 면마다 **날개(풀칠 탭)** 가 붙어 있다. 오려서 접고 풀로
붙이면 끝이다. 뼈대를 따로 찍을 필요가 없고 큐브 하나가 15g 쯤이다.

| 큐브 | 한 변 | 종이 | 장수 |
|---|---|---|---|
| 1 | 130mm | **A4** | 6 |
| 2 | 135mm | **A4** | 6 |
| 3 | 160mm | **A4** | 6 |

🔴 **검출 처리 해상도를 조심할 것.** AR.js 는 영상 크기(sourceWidth)와 검출 처리
크기(canvasWidth)가 따로다. canvasWidth 를 안 주면 기본이 640x480 이라 1280 영상을
반으로 줄여서 읽는다. 그 설정으로 재면 블록 80px 이 나오는데, app.js 는 둘을 같게
주므로 실제로는 45px 이다. 처음에 80px 로 잡아서 마커를 1.8배 크게 만들 뻔했다.

날개는 큐브 모서리 12개에 정확히 하나씩 가도록 나눠 두었다.

| 면 | 날개 |
|---|---|
| 밑면, 윗면 | 네 변 전부 (8개) |
| 옆면 넷 | 오른쪽 한 변만 (4개) |

옆면의 오른쪽 날개는 **다음 번호 옆면**에 붙는다 (+Z 는 +X 에, +X 는 -Z 에).
면 순서가 큐브를 한 바퀴 돈다. 날개는 전부 안쪽으로 접어 넣어서 바깥에는
마커만 보이게 한다.

1. 실선을 오리고 점선을 접는다
2. 밑면 날개 넷을 세우고 옆면 넷을 그 바깥에 붙인다
3. 옆면끼리 오른쪽 날개로 잇는다
4. 윗면 날개 넷을 접어 안으로 넣고 붙인다
5. 윗면 구멍 두 곳에 테이프를 덧대고 뚫어 낚싯줄 두 줄을 꿴다

🔴 **반드시 두 줄로.** 한 줄이면 줄이 꼬여 큐브가 천천히 돈다. 마커가 돌면
샹들리에가 그만큼 통째로 같이 돈다.

### 매단 큐브를 3D 로 찍고 싶으면

`deco/cube/` 에 판 STL 이 있다. 큐브마다 3종류, 6장을 찍는다.

```
python3 deco/make_cube.py deco/cube        # 치수는 config.js 의 CUBE_PLAN 에서 읽는다
```

| 파일 | 장수 | 무엇 |
|---|---|---|
| `cube{N}_side.stl` | 4 | 옆면. 마커를 붙인다 |
| `cube{N}_bottom.stl` | 1 | 밑면. 마커를 붙인다. 안쪽에 턱이 있다 |
| `cube{N}_top.stl` | 1 | 윗면. 낚싯줄 구멍 2개. 마커 없음 |

🔴 **면을 통째로 찍지 않는다.** 205mm 큐브의 겉넓이가 0.21 제곱미터라 1.6mm
벽으로 닫아도 PLA 400g 이 넘는다. 낚싯줄에 매다는 물건에 그 무게는 쓸 데가 없다.
그래서 네모 테두리 + 가운데 십자만 찍고 **면은 마커 인쇄물이 맡는다.**
테두리 8mm 와 십자가 종이를 받쳐 준다. 6장 합쳐 140~200g 이다.

조립 순서. 위아래 판 안쪽에 턱이 있어서 옆면 네 장이 그 안에 끼면 직각이 나온다.
🔴 **비뚤면 다섯 면이 저마다 다른 포즈를 내놓고 앵커가 그걸 평균내서 월드가
흔들린다.** 종이를 똑바로 붙이는 것보다 이게 더 중요하다.

1. 밑면 판에 옆면 네 장을 턱 바깥으로 끼우고 안쪽에서 테이프로 붙인다
2. 윗면 판을 덮는다. 구멍 두 개가 보이는 쪽이 위다
3. 마커를 다섯 면에 붙인다. 옆면은 위쪽이 천장을 향하게, 밑면은 44번 반대쪽
4. 구멍 두 개에 낚싯줄을 꿰어 천장에 맨다

🔴 **반드시 두 줄로.** 한 줄이면 줄이 꼬여 큐브가 천천히 돈다. 마커가 돌면
샹들리에가 그만큼 통째로 같이 돈다. 흔들리는 건 (수 cm) 평활화가 먹는다.

눕혀서 서포트 없이 찍는다. 인필 20% 면 충분하다. 205mm 판이 들어가는 베드가
필요하다 (220x220 이면 된다).

### 매단 큐브를 왜 셋으로 나누는가

바닥 마커는 좌대에 깔려 있는데 관객은 위를 본다. 폰을 1.2m 쯤 위로 겨누는
순간 네 장이 전부 화면에서 빠진다 (세로 화각 65도, 폰 높이 1.5m 기준).
크리스탈이 60초 동안 천(0.52m)에서 샹들리에(2.05m)까지 올라가는 장면이
작품의 핵심인데 그 구간에 기준이 없었다.

### 큐브 밑면이 왜 필요한가

옆면은 세워져 있다. 좌대 바로 앞(축에서 0.6m)에 선 관객이 위를 올려다보면
옆면이 모서리로 보여 안 읽힌다. 모서리 쪽에서는 두 면이 각각 방위 45도
틀어지므로, 시선 고도가 45도만 넘어도 법선과의 각이 60도를 넘는다.
60도가 실측 한계다.

밑면은 법선이 아래라 그 자세에서 가장 정면으로 보인다. 큐브가 가장 약한
자세를 큐브 자신이 메운다. 그래서 천장에 큰 마커를 따로 달 필요가 없어졌다.
윗면은 아무도 못 보므로 비운다.

그래서 바닥 1.25 / 2.15 / 3.05m 에 하나씩 건다. 관객이 1.0~2.0m 뒤 어디에
서서 어느 높이를 겨누든 최소 하나가 화면에 남는다. 한 변은 2.0m 에서도
읽히는 최소값이라 높이 매달수록 커진다. `?arw=1920&arh=1440` 으로 올리면
2/3 로 줄어든다 (대신 프레임이 떨어진다).

## Firebase 설정

**끝났다 (2026-10-29).** 다시 만들 일이 있을 때만 보면 된다.

1. 콘솔에서 **Realtime Database** 를 만든다. Firestore 가 아니다.
   위치는 `asia-southeast1` (싱가포르). 셋 중 한국에서 제일 가깝고 나중에 못 바꾼다.
2. 규칙 탭에 [`hub/firebase_rules.json`](hub/firebase_rules.json) 을 통째로 붙여넣는다.
   crystals 만 읽기가 열리고 그 바깥은 막힌다. 쓰기는 권한 없이는 안 된다.
3. 주소를 `web/config.js` 의 `databaseURL` 에 넣는다. 허브도 이 값을 읽으므로
   주소를 적는 곳은 여기 하나뿐이다.
   SDK 를 안 쓰고 REST 스트리밍을 직접 읽으므로 `apiKey` 도 `projectId` 도 필요 없다.
4. 허브 쓰기 권한은 `hub/secrets.env` 에 넣는다 (`.gitignore` 에 있다).

```
cp hub/secrets.env.example hub/secrets.env
```

5. 확인한다. ESP32 없이 읽기, 쓰기, 지우기를 해 보고 시험용 한 개는 지운다.

```
python3 hub/hub_v1.py --check
```

🔴 데이터베이스 비밀번호는 모든 규칙을 무시하는 관리자 열쇠다. 콘솔에서 사라졌으면
Authentication 에 허브 계정을 만들어 `RAONSUM_FIREBASE_APIKEY` / `_EMAIL` /
`_PASSWORD` 를 쓰면 된다. 허브가 알아서 토큰을 받고 갱신한다.

## 데이터 계약

RTDB `crystals` 아래에 획 하나가 문서 하나로 쌓인다.

| 키 | 범위 | 뜻 |
|---|---|---|
| `press` | 0~1 | 누른 깊이. 크리스탈 두께 |
| `speed` | 0~1 | 빠르기. 투명도 |
| `elong` | 0~1 | 길쭉함. bbox 종횡비 |
| `wind` | 0~1 | 맴돈 정도. 면 분할 |
| `curl` | 마이너스1~1 | 부호 있는 비틀림 |
| `dir` | 라디안 | 시작점에서 끝점 방향 |
| `dur`, `n`, `t`, `feeling` | | 지속시간, 점 수, 시각, v24 의 느낌 이름 |

정규화 범위는 녹화 4개의 획 25개를 실측해서 정했다. press 22~46mm, speed 2~36cm/s.
천 장력이나 센서 높이를 바꾸면 `probe_ranges.py` 를 다시 돌려서 맞춘다.

## 원형 좌대

작품은 둥근 좌대 위에 올라가고 관객은 사방에서 본다. 앞뒤가 없다는 조건이
나머지 기하를 거의 다 정한다.

- **마커는 좌대 안에 들어가야 한다.** 네 장을 천의 네 변 쪽에 하나씩, 테두리
  가까이 놓는다. 전처럼 모서리 쪽(정사각형 배열)에 놓으면 대각선이 길어져
  간격 45cm 에 좌대가 82cm 는 돼야 하는데, 변 쪽으로 돌리면 59cm 면 된다.
  반지름은 `config.js` 의 `refreshPedestal` 이 좌대 지름에서 자동으로 잡는다.
- **높이는 전부 좌대 상단면 기준이다.** 현장에서 줄자로 재면 바닥 기준이
  나오므로 보정 패널이 좌대 높이를 빼고 넘긴다.
- **샹들리에 맨 아래는 머리 위여야 한다.** 관객이 좌대를 돌며 팔 길이 안으로
  들어오므로, 마지막 날 링이 눈높이에 걸리면 크리스탈이 얼굴을 통과한다.
  바닥 기준 `GEOMETRY.headroom` (기본 2.05m) 위로 띄운다.
- **하루 내려오는 높이 = (천장 - headroom) / 27.** 천장 3.4m 면 5.0cm,
  4.0m 면 7.2cm 다. 보정 패널 맨 위에 이 값이 뜬다.

## 마커

AR.js 바코드 마커, 3x3 matrix code 를 쓴다. 값은 0, 7, 44, 63, 26 다섯 개다.
0/7/44/63 은 좌대 위 네 방향, 26 은 천장 뼈대 아랫면이다.
0~4 를 안 쓰는 이유는 3x3 격자가 서로 한 칸밖에 안 달라서다 (회전 포함 최소
거리 1). 이 조합은 최소 거리가 3 이라 한 칸 잘못 읽혀도 다른 마커가 안 된다.

- 바닥 네 개는 한 변 10cm, 천장은 약 30cm
- 무광 인쇄, 평평하게, 네 개를 **같은 방향으로** 붙인다.
  둥근 좌대에는 맞출 모서리가 없으니 테이프로 기준선을 하나 긋고 그 선과
  나란히 붙이는 쪽이 쉽다. 방향이 어긋나면 `yaw` 를 넣어야 한다
- 인쇄물은 `markers/` 에 있다 (`make_pdf.py` 로 PDF 생성)

## 마커를 놓쳐도 되는 이유

샹들리에는 머리 위에 있고 마커는 발밑 좌대에 있다. 그래서 **샹들리에를 보는
자세에서는 마커가 화면에 없는 것이 정상이다.** 자이로 유지(`ANCHOR.gyroHold`)
가 예외 처리가 아니라 기본 동작이라는 뜻이고, 여기에 시간제한을 걸면 안 된다.

자이로는 기기가 돌아간 각도만 알고 관객이 걸어간 거리는 모른다. 그래서
좌대를 돌면 조금씩 어긋나고, `ANCHOR.hintSeconds` 뒤에 다시 비춰 달라고
안내한다. 다시 잡은 포즈가 `ANCHOR.snapMeters` 넘게 다르면 저역 필터로
따라가지 않고 한 번에 끊어서 맞춘다. 안 그러면 샹들리에가 공중을 가로질러
미끄러져 오는 게 보인다.

## 전시 전 체크리스트

- [ ] 좌대 **지름과 높이** 실측. 이 둘이 마커 반지름과 모든 높이를 정한다
- [ ] 현장에서 `?debug=1` 보정 패널에 바닥에서 천장까지, 좌대 높이, 좌대 지름을
      넣고 뜨는 값을 `config.js` 기본값에 적어 넣기
- [ ] 현장에서 `?debug=1` 로 월드 원점을 보면서 마커 위치와 `yaw` 맞추기
- [ ] 좌대를 한 바퀴 돌며 어느 방향에서도 마커가 하나는 잡히는지 확인
- [ ] A-Frame 과 AR.js 를 CDN 에서 저장소로 **내려받아 고정**하기.
      3주 무인 운영에서 외부 CDN 의 경로 변경이나 장애가 작품을 죽인다
- [ ] 아이폰과 안드로이드 실기 테스트. **카카오톡으로 QR 을 스캔한 경우**를 꼭 포함
- [ ] 포스터에 "휴대폰 카메라 앱으로 스캔" 문구
- [ ] 크리스탈이 많이 쌓인 상태에서 오래된 폰 성능 확인
- [ ] 누적 리셋 규칙 (시간 기준 또는 개수 기준) 결정하고 넣기

## 아직 비어 있는 것

1. **크리스탈 생김새.** `crystal.js` 는 임시 팔면체다. 디자인이 오면 이 파일만 바꾸면 된다.
   바깥과의 약속은 `makeCrystal(data)` 와 `setQuality(mesh, level)` 두 개뿐이다.
2. **기하 실측값.** 좌대 지름과 높이, 바닥에서 천장까지, 매단 링 반지름.
3. **천장에 매달 수 있는지.** 안 되면 기울기 센서 차선책으로 구현이 달라진다.
