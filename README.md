# 가상 샹들리에

Playground 파생작. 천 위에 손가락으로 그리면 크리스탈 하나가 태어나 천장의
가상 샹들리에에 매달린다. 관객은 자기 폰으로 QR 을 스캔해서 본다.

```
천 + ToF 9개 -> ESP32 -> (USB) -> 허브 -> Firebase -> 관객 폰 웹 AR
```

## 관객이 여는 주소

**https://jwyang29.github.io/raonsum-chandelier/**

## 로컬에서 보기

```
python3 -m http.server 5604 --directory web
```

열 때 쿼리를 붙인다.

| 쿼리 | 하는 일 |
|---|---|
| `?preview=1` | 마커도 카메라도 없이 샹들리에만 본다. 폰 성능을 보는 자리다 |
| `?mock=1` | Firebase 없이 가짜 크리스탈을 4초마다 만든다 |
| `?fill=1` | 쌓인 상태로 시작한다. `?fill=60` 처럼 개수도 준다 |
| `?desk=1` | 책상 시험용. 샹들리에를 마커 위 0.30~0.70m 로 줄인다 |
| `?msize=0.062` | 마커 검은 사각형의 실제 한 변 (m) |
| `?guide=1` | 마커 평면에 실측 윤곽과 1m 자를 그린다. 월드가 실물에 맞는지 본다 |
| `?debug=1` | 마커 수, 크리스탈 수, 품질 단계, fps, 월드 원점, 실측값을 표시한다 |
| `?intro=0` | AR 첫 화면 안내를 건너뛴다. 현장에서 반복해서 들어갈 때 |
| `?far=2.4` | "가까이 오세요" 가 뜨는 거리 (m). `?above=`, `?ghold=` 도 같이 |

카메라는 HTTPS 또는 localhost 에서만 열린다. 폰으로 볼 때는 GitHub Pages 에 올려야 한다.

### 인쇄 전에 폰으로 확인하는 법

🔴 `?mock=1` 만 붙이면 **아무것도 안 보이는 게 정상이다.** AR 모드는 빈 상태로
시작하고(쌓인 것은 Firebase 에서 받는다), 샹들리에는 마커에서 1.7~3.1m 위라
책상에 놓은 마커를 비추면 화면 한참 위에 있다.

1. 노트북 화면에 마커를 띄우고 **검은 사각형을 자로 잰다**.
2. 폰에서 `?mock=1&fill=1&desk=1&msize=잰값&debug=1` 로 연다.
3. 진단 패널의 `보이는 마커` 가 올라가면 검출까지 된 것이다.

`msize` 를 안 주면 월드 전체가 그만큼 작아진다. AR.js 는 적어 놓은 마커 크기로
거리를 풀기 때문이다. 화면의 CSS mm 는 실제 mm 가 아니다.

### 인쇄

🔴 **`markers/print/` 의 PDF 로 100% 배율로 찍을 것.** SVG 를 브라우저에서
인쇄하면 여백에 맞춰 줄어든다. 찍고 나서 **자로 검은 사각형을 재서 100mm 인지
확인한다.** 여기가 틀리면 월드 전체의 크기가 그 비율로 틀어진다.
100mm 로 못 찍었으면 `web/config.js` 의 `markerSize` 를 실측값으로 고친다.

| 파일 | 내용 |
|---|---|
| `RAONSUM_markers_A4_ALL.pdf` | **마커 전부. A4 15장 한 파일.** 각 면만, 한 장에 최대한 담았다 |
| `RAONSUM_markers_A4_ALL_tabs.pdf` | 종이로 접어 만들던 옛 판. 날개와 접는 선이 있다 |
| `RAONSUM_markers_A4_ALL_top.pdf` | 큐브1 윗면에도 마커를 넣은 판. 아래 설명을 읽고 쓸 것 |
| `RAONSUM_layout_1_floor_A4.svg` | **바닥 배치도.** 실제 마커 그림으로 그렸다. 실측값 적는 칸 포함 |
| `RAONSUM_layout_2_cubes_A4.svg` | **큐브 면 배치도.** 열다섯 면의 실제 그림 |

배치도 두 장은 `markers/layout_preview.html` 을 브라우저에서 열어 인쇄한다.

합친 파일의 구성이다.

| 쪽 | 무엇 | 검은 사각형 |
|---|---|---|
| 2~5 | 바닥 4장 (0, 7, 44, 63) | 100mm |
| 6~11 | 큐브1 (옆면 4 + 밑면 + 윗면) | 86.7mm |
| 12~17 | 큐브2 | 90.0mm |
| 18~23 | 큐브3 | 106.7mm |
| 24 | 천장 (선택) | 133mm |

🔴 **따로 열어 찍지 말 것.** 스물네 장이 다 비슷하게 생겨서 한 장이 빠져도
모른다. 한 파일로 한 번에 찍고 1쪽 차례로 센다.

무광으로, **흰 여백은 자르지 말 것.** 여백이 없으면 검출기가 사각형을 못 찾는다.

다시 뽑을 때. 배치도는 `config.js` 에서 치수를 읽어 오므로 좌대를 실측해서
고치면 다시 돌려야 한다.

```
python3 markers/make_pdf.py markers/print            # 마커. --cube 160 으로 큐브 크기 변경
python3 markers/make_pdf.py markers/print --tabs    # 종이로 접어 만들 때 (날개 붙음)
python3 markers/make_pdf.py markers/print --index   # 맨 앞에 차례를 붙인다
python3 markers/pick_top_codes.py                   # 윗면에 쓸 번호가 있는지 본다
python3 markers/make_layout.py markers/print         # 배치도 SVG
```

배치도는 브라우저에서 열어 인쇄하면 된다. 배율이 틀어져도 상관없는 참고용이다.

### 매단 큐브 만들기 (종이)

큐브 PDF 가 전개도다. 면마다 **날개(풀칠 탭)** 가 붙어 있다. 오려서 접고 풀로
붙이면 끝이다. 뼈대를 따로 찍을 필요가 없고 큐브 하나가 15g 쯤이다.

| 큐브 | 한 변 | 종이 | 장수 |
|---|---|---|---|
| 1 | 130mm | **A4** | 6 |
| 2 | 135mm | **A4** | 6 |
| 3 | 160mm | **A4** | 6 |

🔴 **검출 처리 해상도를 조심할 것.** AR.js 는 영상 크기(sourceWidth)와 검출 처리
크기(canvasWidth)가 따로다. canvasWidth 를 안 주면 기본이 640x480 이라 1280 영상을
반으로 줄여서 읽는다. 그 설정으로 재면 블록 80px 이 나오는데, app.js 는 둘을 같게
주므로 실제로는 45px 이다. 처음에 80px 로 잡아서 마커를 1.8배 크게 만들 뻔했다.

날개는 큐브 모서리 12개에 정확히 하나씩 가도록 나눠 두었다.

| 면 | 날개 |
|---|---|
| 밑면, 윗면 | 네 변 전부 (8개) |
| 옆면 넷 | 오른쪽 한 변만 (4개) |

옆면의 오른쪽 날개는 **다음 번호 옆면**에 붙는다 (+Z 는 +X 에, +X 는 -Z 에).
면 순서가 큐브를 한 바퀴 돈다. 날개는 전부 안쪽으로 접어 넣어서 바깥에는
마커만 보이게 한다.

1. 실선을 오리고 점선을 접는다
2. 밑면 날개 넷을 세우고 옆면 넷을 그 바깥에 붙인다
3. 옆면끼리 오른쪽 날개로 잇는다
4. 윗면 날개 넷을 접어 안으로 넣고 붙인다
5. 윗면 구멍 두 곳에 테이프를 덧대고 뚫어 낚싯줄 두 줄을 꿴다

🔴 **반드시 두 줄로.** 한 줄이면 줄이 꼬여 큐브가 천천히 돈다. 마커가 돌면
샹들리에가 그만큼 통째로 같이 돈다.

### 매단 큐브를 3D 로 찍고 싶으면

`deco/cube/` 에 판 STL 이 있다. 큐브마다 3종류, 6장을 찍는다.

```
python3 deco/make_cube.py deco/cube        # 치수는 config.js 의 CUBE_PLAN 에서 읽는다
```

| 파일 | 장수 | 무엇 |
|---|---|---|
| `cube{N}_side.stl` | 4 | 옆면. 마커를 붙인다 |
| `cube{N}_bottom.stl` | 1 | 밑면. 마커를 붙인다. 안쪽에 턱이 있다 |
| `cube{N}_top.stl` | 1 | 윗면. 낚싯줄 구멍 2개. 마커 없음 |

🔴 **면을 통째로 찍지 않는다.** 205mm 큐브의 겉넓이가 0.21 제곱미터라 1.6mm
벽으로 닫아도 PLA 400g 이 넘는다. 낚싯줄에 매다는 물건에 그 무게는 쓸 데가 없다.
그래서 네모 테두리 + 가운데 십자만 찍고 **면은 마커 인쇄물이 맡는다.**
테두리 8mm 와 십자가 종이를 받쳐 준다. 6장 합쳐 140~200g 이다.

조립 순서. 위아래 판 안쪽에 턱이 있어서 옆면 네 장이 그 안에 끼면 직각이 나온다.
🔴 **비뚤면 다섯 면이 저마다 다른 포즈를 내놓고 앵커가 그걸 평균내서 월드가
흔들린다.** 종이를 똑바로 붙이는 것보다 이게 더 중요하다.

1. 밑면 판에 옆면 네 장을 턱 바깥으로 끼우고 안쪽에서 테이프로 붙인다
2. 윗면 판을 덮는다. 구멍 두 개가 보이는 쪽이 위다
3. 마커를 다섯 면에 붙인다. 옆면은 위쪽이 천장을 향하게, 밑면은 44번 반대쪽
4. 구멍 두 개에 낚싯줄을 꿰어 천장에 맨다

🔴 **반드시 두 줄로.** 한 줄이면 줄이 꼬여 큐브가 천천히 돈다. 마커가 돌면
샹들리에가 그만큼 통째로 같이 돈다. 흔들리는 건 (수 cm) 평활화가 먹는다.

눕혀서 서포트 없이 찍는다. 인필 20% 면 충분하다. 205mm 판이 들어가는 베드가
필요하다 (220x220 이면 된다).

### 매단 큐브를 왜 셋으로 나누는가

바닥 마커는 좌대에 깔려 있는데 관객은 위를 본다. 폰을 1.2m 쯤 위로 겨누는
순간 네 장이 전부 화면에서 빠진다 (세로 화각 65도, 폰 높이 1.5m 기준).
크리스탈이 60초 동안 천(0.52m)에서 샹들리에(2.05m)까지 올라가는 장면이
작품의 핵심인데 그 구간에 기준이 없었다.

### 큐브 밑면이 왜 필요한가

옆면은 세워져 있다. 좌대 바로 앞(축에서 0.6m)에 선 관객이 위를 올려다보면
옆면이 모서리로 보여 안 읽힌다. 모서리 쪽에서는 두 면이 각각 방위 45도
틀어지므로, 시선 고도가 45도만 넘어도 법선과의 각이 60도를 넘는다.
60도가 실측 한계다.

밑면은 법선이 아래라 그 자세에서 가장 정면으로 보인다. 큐브가 가장 약한
자세를 큐브 자신이 메운다. 그래서 천장에 큰 마커를 따로 달 필요가 없어졌다.
윗면은 아무도 못 보므로 비운다.

그래서 바닥 1.25 / 2.15 / 3.05m 에 하나씩 건다. 관객이 1.0~2.0m 뒤 어디에
서서 어느 높이를 겨누든 최소 하나가 화면에 남는다. 한 변은 2.0m 에서도
읽히는 최소값이라 높이 매달수록 커진다. `?arw=1920&arh=1440` 으로 올리면
2/3 로 줄어든다 (대신 프레임이 떨어진다).

## Firebase 설정

**끝났다 (2026-10-29).** 다시 만들 일이 있을 때만 보면 된다.

1. 콘솔에서 **Realtime Database** 를 만든다. Firestore 가 아니다.
   위치는 `asia-southeast1` (싱가포르). 셋 중 한국에서 제일 가깝고 나중에 못 바꾼다.
2. 규칙 탭에 [`hub/firebase_rules.json`](hub/firebase_rules.json) 을 통째로 붙여넣는다.
   crystals 만 읽기가 열리고 그 바깥은 막힌다. 쓰기는 권한 없이는 안 된다.
3. 주소를 `web/config.js` 의 `databaseURL` 에 넣는다. 허브도 이 값을 읽으므로
   주소를 적는 곳은 여기 하나뿐이다.
   SDK 를 안 쓰고 REST 스트리밍을 직접 읽으므로 `apiKey` 도 `projectId` 도 필요 없다.
4. 허브 쓰기 권한은 `hub/secrets.env` 에 넣는다 (`.gitignore` 에 있다).

```
cp hub/secrets.env.example hub/secrets.env
```

5. 확인한다. ESP32 없이 읽기, 쓰기, 지우기를 해 보고 시험용 한 개는 지운다.

```
python3 hub/hub_v1.py --check
```

🔴 데이터베이스 비밀번호는 모든 규칙을 무시하는 관리자 열쇠다. 콘솔에서 사라졌으면
Authentication 에 허브 계정을 만들어 `RAONSUM_FIREBASE_APIKEY` / `_EMAIL` /
`_PASSWORD` 를 쓰면 된다. 허브가 알아서 토큰을 받고 갱신한다.

## 데이터 계약

RTDB `crystals` 아래에 획 하나가 문서 하나로 쌓인다.

| 키 | 범위 | 뜻 |
|---|---|---|
| `press` | 0~1 | 누른 깊이. 크리스탈 두께 |
| `speed` | 0~1 | 빠르기. 투명도 |
| `elong` | 0~1 | 길쭉함. bbox 종횡비 |
| `wind` | 0~1 | 맴돈 정도. 면 분할 |
| `curl` | 마이너스1~1 | 부호 있는 비틀림 |
| `dir` | 라디안 | 시작점에서 끝점 방향 |
| `dur`, `n`, `t`, `feeling` | | 지속시간, 점 수, 시각, v24 의 느낌 이름 |

정규화 범위는 녹화 4개의 획 25개를 실측해서 정했다. press 22~46mm, speed 2~36cm/s.
천 장력이나 센서 높이를 바꾸면 `probe_ranges.py` 를 다시 돌려서 맞춘다.

## 원형 좌대

작품은 둥근 좌대 위에 올라가고 관객은 사방에서 본다. 앞뒤가 없다는 조건이
나머지 기하를 거의 다 정한다.

- **마커는 좌대 안에 들어가야 한다.** 네 장을 천의 네 변 쪽에 하나씩, 테두리
  가까이 놓는다. 전처럼 모서리 쪽(정사각형 배열)에 놓으면 대각선이 길어져
  간격 45cm 에 좌대가 82cm 는 돼야 하는데, 변 쪽으로 돌리면 59cm 면 된다.
  반지름은 `config.js` 의 `refreshPedestal` 이 좌대 지름에서 자동으로 잡는다.
- **높이는 전부 좌대 상단면 기준이다.** 현장에서 줄자로 재면 바닥 기준이
  나오므로 보정 패널이 좌대 높이를 빼고 넘긴다.
- **샹들리에 맨 아래는 머리 위여야 한다.** 관객이 좌대를 돌며 팔 길이 안으로
  들어오므로, 마지막 날 링이 눈높이에 걸리면 크리스탈이 얼굴을 통과한다.
  바닥 기준 `GEOMETRY.headroom` (기본 2.05m) 위로 띄운다.
- **하루 내려오는 높이 = (천장 - headroom) / 27.** 천장 3.4m 면 5.0cm,
  4.0m 면 7.2cm 다. 보정 패널 맨 위에 이 값이 뜬다.

## 마커

AR.js 바코드 마커, 3x3 matrix code 를 쓴다. 값은 0, 7, 44, 63, 26 다섯 개다.
0/7/44/63 은 좌대 위 네 방향, 26 은 천장 뼈대 아랫면이다.
0~4 를 안 쓰는 이유는 3x3 격자가 서로 한 칸밖에 안 달라서다 (회전 포함 최소
거리 1). 이 조합은 최소 거리가 3 이라 한 칸 잘못 읽혀도 다른 마커가 안 된다.

- 바닥 네 개는 한 변 10cm, 천장은 약 30cm
- 무광 인쇄, 평평하게, 네 개를 **같은 방향으로** 붙인다.
  둥근 좌대에는 맞출 모서리가 없으니 테이프로 기준선을 하나 긋고 그 선과
  나란히 붙이는 쪽이 쉽다. 방향이 어긋나면 `yaw` 를 넣어야 한다
- 인쇄물은 `markers/` 에 있다 (`make_pdf.py` 로 PDF 생성)

## 마커를 놓쳐도 되는 이유

샹들리에는 머리 위에 있고 마커는 발밑 좌대에 있다. 그래서 **샹들리에를 보는
자세에서는 마커가 화면에 없는 것이 정상이다.** 자이로 유지(`ANCHOR.gyroHold`)
가 예외 처리가 아니라 기본 동작이라는 뜻이고, 여기에 시간제한을 걸면 안 된다.

자이로는 기기가 돌아간 각도만 알고 관객이 걸어간 거리는 모른다. 그래서
좌대를 돌면 조금씩 어긋나고, `ANCHOR.hintSeconds` 뒤에 다시 비춰 달라고
안내한다. 다시 잡은 포즈가 `ANCHOR.snapMeters` 넘게 다르면 저역 필터로
따라가지 않고 한 번에 끊어서 맞춘다. 안 그러면 샹들리에가 공중을 가로질러
미끄러져 오는 게 보인다.

## 몇 명이 열어 봤는지

```
python3 hub/visits.py
python3 hub/visits.py --days 7
```

```
날짜            열람     AR     시작
---------------------------------
2026-11-12       14      6       5
```

🔴 **사람 수가 아니라 열어 본 횟수다.** 관객을 구분할 수 있는 것을 하나도
안 남긴다. 아이피도 기기 정보도 식별자도 없다. 남는 것은 밀리초 시각 하나다.

    visits/2026-11-12/home/<자동키> = 1762934...

같은 사람이 다음 날 또 와도 다른 사람과 구별되지 않는다. 그건 못 세는 게
아니라 안 세는 것이다. 한 번 열고 새로고침을 열 번 해도 한 번만 센다 (탭 단위).

세 칸의 뜻은 이렇다.

| 칸 | 뜻 |
|---|---|
| 열람 | 설명 페이지를 열었다. QR 을 찍은 사람이다 |
| AR | AR 보기까지 눌렀다 |
| 시작 | 안내를 읽고 시작하기를 눌렀다. 카메라를 허락할 기회까지 갔다 |

열람과 AR 의 차이가 설명만 보고 돌아간 사람이고, AR 과 시작의 차이가 첫
화면에서 그만둔 사람이다. 무인 전시라 이 두 숫자 말고는 어디서 놓치는지
알 길이 없다.

⚠️ `hub/firebase_rules.json` 을 콘솔 규칙 탭에 다시 붙여넣고 게시해야 쌓이기
시작한다. 게시 전까지는 관객 폰이 조용히 실패한다 (화면은 멀쩡하다).


## 유리 질감 맞추기

```
/glasstest.html
```

왼쪽은 2026-11-12 이전 모습으로 고정되어 있고 오른쪽만 슬라이더로 움직인다.
**검정 / 흰 벽 / 전시장** 배경을 꼭 바꿔 가며 본다. 전시장이 화이트큐브라
검정에서 맞춘 유리는 흰 벽 앞에서 사라진다.

맞는 값을 찾으면 `지금 값을 주소로 복사` 를 누른다. 그 주소를 폰에서 열면
현장 조명 아래에서 바로 보이고, 괜찮으면 `web/config.js` 의 `GLASS` 에 박는다.

| 주소 | 바뀌는 것 |
|---|---|
| `?sparkle=2.2` | 하이라이트 세기 |
| `?specpow=240` | 하이라이트 날카로움 |
| `?disp=0.04` | 분산. 반짝일 때 색이 갈라지는 정도 |
| `?flash=0.3` | 가장자리에 서는 테두리 |
| `?rolloff=0` | **11-12 이전 모습으로 되돌린다** |
| `?absorb=0.5` | 두께로 먹는 빛. 흰 벽에서 형태가 읽히는 정도 |

🔴 `specPower` / `dispersion` / `flash` 는 2026-11-12 까지 셰이더에서 아예
안 쓰이고 있었다. `disperse()` 는 함수까지 써 놓고 한 번도 부르지 않았고,
날카로움은 `GLASS.specPower` 대신 `96.0` 이 박혀 있었다. `alphaCore` /
`alphaRim` 때와 같은 종류다. 셋 다 살렸다.

⚠️ 그래서 지금 숫자는 **눈으로 맞춘 값이 아니다.** `flash` 만 재서 0.12 로
잡았다 (0.6 이면 화면 평균 밝기가 10.9 에서 21.4 로 뛰고 몸통이 허옇게 뜬다).
나머지는 현장에서 한 번 봐야 한다.


## 한 장에 몇 개가 들어가나

표지를 빼고, 사각형을 한 장에 최대한 담는다. **24장이 15장이 됐다.**

🔴 **가로로 둘을 못 놓는다.** 가장 작은 둘도 130 + 130 = 260 인데 A4 에서 쓸
수 있는 폭이 194mm 다. 그래서 세로 한 줄로만 쌓는다.

🔴 **사이를 띄우지 않는다.** 맞닿은 두 사각형은 한 번 자르면 둘로 갈라진다.
포맥스 재단 때와 같은 원리다. 띄우면 150 + 130 = 280 이 281 을 넘어 짝이
깨지고 넉 장이 더 든다.

🔴 **글자는 사각형 오른쪽 띠에 적는다.** 위에 적으면 한 장당 10mm 씩 먹어서
짝이 깨진다 (135 + 9 + 135 + 9 = 288 > 281). 배율 확인용 100mm 자도 맨
오른쪽에 세로로 둔다.

| 쪽 | 들어간 것 |
|---|---|
| 1~6 | 큐브3 여섯 면 (160mm). 혼자 한 장씩 |
| 7~10 | 바닥 1~4 + 큐브1 옆면 (150 + 130) |
| 11~13 | 큐브2 여섯 면 (135 둘씩) |
| 14 | 큐브1 밑면 + 윗면 (130 둘) |
| 15 | 천장 (200mm. 폭이 194mm 를 넘어 혼자 쓴다) |

**A4 로는 15장이 최소다.** 160mm 여섯 장은 아래에 121mm 가 남지만 제일 작은
사각형이 130mm 라 아무것도 안 들어간다. 나머지 2190mm 는 281mm 칸 네 개가
최소이므로 6 + 4 + 4 = 14 장이 하한이고, 천장 한 장을 더해 15장이다.

표지가 필요하면 `--index` 다.

## 큐브 마커는 왜 각 면만인가

큐브를 3mm 포맥스로 다시 만들었다. 접을 일이 없으므로 날개도 접는 선도
없앴다. 면마다 한 장씩, 오릴 선 하나와 마커만 있다. 오려서 면에 붙인다.

덤으로 큐브3(160mm)이 A4 에 여유 있게 들어간다 (160 + 16 = 176mm). 날개가
있을 때는 184mm 라 가장자리에 바짝 붙어 프린터가 줄여 버릴 수 있었다.

종이로 접어 만들던 판이 필요하면 `--tabs` 다.

## 큐브 윗면 마커를 기본으로 안 넣은 이유

두 가지다. 둘 다 재서 나온 것이다.

윗면 종이에는 **사각형만** 그린다. 치수 글씨도 구멍 표시도 안 넣는다.
구멍은 포맥스에 이미 뚫려 있으므로, 종이에 미리 찍으면 오히려 어긋난다.

**1. 관객 폰에서 거의 안 보인다.** 폰을 1.50m 높이로 들고 큐브 축에서
0.60m 떨어져 서면, 윗면 법선과 시선의 각이 이렇다.

| | 윗면 높이 | 법선과의 각 | |
|---|---|---|---|
| 큐브1 | 1.39 m | **79도** | 안 읽힘 |
| 큐브2 | 1.84 m | **119도** | 등을 돌림 |
| 큐브3 | 2.32 m | **144도** | 등을 돌림 |

실측 한계가 60도다. 큐브1 윗면이 60도 안에 들어오려면 폰을 **1.73m** 까지,
머리 위로 들어 올려야 한다.

**2. 쓸 번호가 없다.** 3x3 격자 64개 중 지금 쓰는 18개와 회전까지 넣어
거리 2 이상인 남은 번호는 **35 와 37 둘뿐**이다 (`markers/pick_top_codes.py`).
큐브는 셋이라 하나는 거리 1 짜리를 써야 하는데, 거리 1 은 칸 하나만 잘못
읽혀도 바닥 마커로 둔갑한다. 그러면 월드 원점이 큐브 자리로 날아간다.

그래도 넣겠다면 `--cubetop` 이다. 큐브1 에만 37 이 들어간다 (제 밑면과
거리 4, 나머지 전부와 2). 큐브2 에도 넣겠다면 35 가 남아 있고, 큐브3 은
안전한 번호가 없다.

⚠️ 인쇄만으로는 안 된다. `web/config.js` 도 같이 켜야 검출기가 그 번호를
찾는다. 안 켜면 붙여 놔도 그냥 무시된다 (해롭지는 않다).

## 인쇄물의 마커 반지름은 어디서 오나

`make_pdf.py` 가 Firebase `/cal` 의 `mring` 을 읽는다. 없으면 `config.js` 에서
계산한다. 🔴 설치 뒤에 실측해서 넣은 값은 `config.js` 가 아니라 `/cal` 에
있다. config 기본값으로는 420mm 가 나오는데 현장은 450mm 다. 그 차이대로
붙이면 마커가 3cm 씩 틀어진다. 망이 없으면 화면에 그렇다고 적어 준다.


## 시연 당일 순서 (11/14, 11/15)

노트북 한 대, ESP32 USB 하나. 순서대로만 하면 된다.

**집에서 나오기 전**

```bash
python3 hub/setcal.py --scatter 0
```

흩뿌리기를 끈다. 안 끄면 관객이 그린 것이 샹들리에에 안 붙고 허공에 흩어진다.

**1. 센서부터 본다 (Firebase 안 건드림)**

```bash
python3 hub/hub_v1.py --selftest
```

포트를 알아서 찾는다. 한 줄이 계속 덮어쓰이며 이렇게 나온다.

```
 32.4 fps    60   66   82   86   72   76   87   86   81   전부 읽힘
```

`--` 가 있으면 그 번호 센서가 안 읽히는 것이다. 배선이나 I2C 주소를 본다.
처음 2초는 천에서 손을 뗀다 (기준 거리). 그다음 천을 그어 보면 획이 잡힌다.
Ctrl+C 로 끝내면 몇 개를 잡았는지 알려 준다.

**2. 망을 본다 (ESP32 안 건드림)**

```bash
python3 hub/hub_v1.py --check
```

읽기, 쓰기, 지우기를 차례로 해 보고 시험용 한 개를 치운다.

**3. 사슬 전체를 시험 자리에서 본다**

```bash
python3 hub/hub_v1.py --path crystals_test
```

폰에서 이 주소를 연다. 천에 그으면 몇 초 안에 크리스탈이 하나 떠야 한다.

```
.../ar.html?dbpath=crystals_test&feed=live&preview=1
```

🔴 `--path` 를 빼먹으면 관객이 보는 자리에 시험 크리스탈이 섞인다.

**4. 전시용으로 돌린다**

```bash
python3 hub/hub_v1.py
```

한 줄이 계속 보인다.

```
 32.4 fps   센서 9/9   기준 OK   손 ●   획 7   올림 7
```

| 보이는 것 | 뜻 |
|---|---|
| `센서 9/9` | 아홉 개가 다 살아 있다 |
| `기준 잡는 중 23` | 아직 기준 거리를 재는 중. 천에서 손을 떼고 기다린다 |
| `손 ●` | 지금 누가 천을 누르고 있다 |
| `대기 3` | 망이 끊겨 세 개가 못 올라갔다. 붙으면 알아서 올라간다 |
| `실패 5` | 지금까지 다섯 번 실패했다 |

**끊겨도 알아서 붙는다.** USB 가 건드려지거나 ESP32 가 리셋되면 다시 연결하고
기준 거리를 다시 잰다. 그때 "천에서 손을 떼 주세요" 가 뜬다.

**못 올린 것은 안 버린다.** `hub/outbox.json` 에 받쳐 두고 다음에 켤 때 마저
올린다. 와이파이가 끊긴 채로 시연이 끝나도 그 시간 관객 것이 살아 있다.

### 막혔을 때

| 증상 | 볼 곳 |
|---|---|
| 포트를 못 찾는다 | `python3 hub/hub_v1.py --ports` 로 뭐가 보이는지 확인 |
| 센서가 `--` | 배선, I2C 주소. `--selftest` 로 번호를 본다 |
| 획이 안 잡힌다 | 천을 더 깊게 누른다. 기준 거리를 다시 (Ctrl+C 후 재실행) |
| 올라가는데 폰에 안 뜬다 | 폰이 `crystals` 를 보는지. `--path` 를 켜 두지 않았는지 |
| 폰에 아무것도 없다 | 마커를 비추고 폰을 들어 올린다. 안내 문구를 따른다 |

🔴 **ESP32 펌웨어는 이 저장소에 없다.** 보드에 이미 올라가 있는 것을 쓴다.
`D,<d0>,...,<d8>` 을 115200 으로 보내는 펌웨어다. 보드를 다시 구워야 하는
상황이 오면 소스가 없으므로, 여분 보드가 있다면 미리 확인해 둘 것.
